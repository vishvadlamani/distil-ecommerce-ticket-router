# Ecommerce Support Ticket Router

A fine-tuned Qwen3-1.7B that reads a support ticket plus light order metadata and emits one routable JSON object. On the 24-ticket held-out benchmark it scores 83.3 percent against its 120B teacher's 75.0 percent, with valid JSON on 100 percent of 94 evaluated inputs, running locally at about 1.9 seconds per ticket on a laptop. Trained on the [Distil Labs](https://www.distillabs.ai) platform. Weights: [vishinvents/distil-qwen3-1.7b-ecom-ticket-router](https://huggingface.co/vishinvents/distil-qwen3-1.7b-ecom-ticket-router).

Every ticket in, one object out:

```json
{
  "intent": "delivery_issue",
  "urgency": 4,
  "order_id": "AC-92831",
  "sentiment": "frustrated",
  "suggested_action": "open_carrier_investigation",
  "needs_human": false
}
```

## Results

Measured, not estimated. Three models on the same 64-row held-out test (24 curated tickets plus 40 real customer messages), scored by the platform's LLM judge:

| | Untrained Qwen3-1.7B | Teacher (gpt-oss-120b) | Tuned Qwen3-1.7B |
|---|---|---|---|
| LLM-as-a-judge | 32.8% | 67.2% | **67.2%** |
| Exact match | 0.0% | 56.3% | 54.7% |
| ROUGE | 82.6% | 90.1% | **90.7%** |

Split by slice, same field-level grader on both models:

| Slice | Teacher | Tuned student |
|---|---|---|
| Curated benchmark (24 tickets, in-domain) | 75.0% | **83.3%** |
| Real customer messages (40 tweets, out-of-domain) | **60.0%** | 57.5% |

The student beats its teacher in the domain it was built for and stays within one ticket of it on raw out-of-domain social messages. Format reliability is the clean sweep: the tuned model produced schema-valid JSON on all 94 local evaluation inputs, including Spanish, German, emoji, and prompt-injection attempts. The teacher dropped two.

A ticket passes the judge only when intent, order id, and the human-escalation flag are exact, urgency is within one, and the action is allowed for the intent. Single-field accuracy runs higher: on the curated set the tuned model reads intent at 95.8 percent and copies order ids at 100 percent.

## Quickstart

Needs [Ollama](https://ollama.com) and [bun](https://bun.sh).

```bash
# fetch the GGUF and Modelfile from the HF repo, then:
ollama create ecom-router-1.7b-v5 -f Modelfile
bun install
bun run demo
```

The demo routes six tickets that show the behavior worth having: the same words classified differently when the order metadata contradicts them, cancellation flipping between automated and escalated depending on shipment state, a repeat contact forcing a human, and a prompt-injection attempt getting classified instead of obeyed.

`bun run eval` reruns the 24-ticket benchmark plus a 30-ticket adversarial battery locally. `bun run eval-real` reruns the 40 real messages.

## How it routes

- **intent**, one of 12: order_status, delivery_issue, return_request, refund_status, exchange, cancellation, product_question, sizing_fit, damaged_item, billing_issue, account_access, other
- **urgency** 1 to 5 on a fixed rubric
- **order_id** copied character for character from the ticket, metadata as fallback, null when absent. The ticket text wins when the two disagree.
- **sentiment**: angry, frustrated, neutral, positive
- **suggested_action**, one of 13 closed actions, constrained per intent (the table lives in [src/types.ts](src/types.ts))
- **needs_human** from explicit triggers: threats, fraud signals, repeat contact, requests for a person, anything automation cannot resolve

The model reasons over ticket plus metadata together. "Where is my order" with a package in transit for two days gets a tracking link. The same sentence with the carrier reporting delivery six days ago is a lost package and opens a carrier investigation. Keyword rules cannot make that distinction; this is the argument for a model in the loop.

[src/dispatch.ts](src/dispatch.ts) is the production wrapper: schema validation with one retry, fail-closed to a human on unusable output, and mechanical clamps for the contract's hard rules. Clamp rates are surfaced per decision so drift is visible in monitoring.

## Training data

The full loop is in this repo and reproducible without a frontier API key:

1. **73 hand-authored seeds** ([scripts/build_seeds.ts](scripts/build_seeds.ts)): 49 train, 24 test, validated for schema, action coherence, verbatim ids, and split hygiene. Contrast pairs sit on every confusable boundary.
2. **10,149 synthetic tickets** generated by the platform's teacher from the seeds.
3. **Mechanical label repair** ([scripts/repair_training_data.ts](scripts/repair_training_data.ts)): 409 generated rows violated the contract's hard rules (escalation logic, action table, repeat-contact handling); a further 1,114 taught over-escalation. Both classes repaired by rule, not by hand. Training on repaired labels is how the student passes its teacher: the teacher's mistakes stop being the ceiling.
4. **60 hand-labeled real customer messages** (public Twitter customer-support corpus) folded into training; 40 more held out as the out-of-domain test, labeled before any model ran on them.
5. Six hand-written manipulation tickets teach injection handling: pure overrides get ignored, entitlement claims escalate to a person, injections wrapped around a real request get routed on the real request.

## Limitations

English-first: the model answers non-English tickets in valid JSON but with reduced accuracy. Raw social-media messages without order metadata sit outside the training distribution; accuracy there is 57.5 percent against the teacher's 60.0. Escalation boundaries the contract leaves implicit (return windows, stuck-order thresholds) are learned from seed policy and drift on edge cases. Latency was measured on an Apple M-series laptop with the f16 weights; smaller quantizations were not evaluated.
